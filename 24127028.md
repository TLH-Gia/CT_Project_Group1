# Vietnamese food detection

The goal is to enable machines to recognize food accurately and efficiently for applications such as dietary assessment, food safety, restaurant automation, and nutritional tracking.

Key aspects of the food detection problem definition:

*Input:* Raw image or video frame potentially containing one or multiple food items, often with varying backgrounds, occlusions, and lighting conditions.

*Output:*
Food classification: Assigning one or multiple food category labels to the detected food items.
Localization: Identifying the spatial location in the image of each detected food item, typically using bounding boxes or segmentation masks.

*Constraint:*
There are only 67 dishes available for training. Also, the additional information including recipe, nutrition value, origin and variants of dishes would be attached to the dish label instead of being processed on user input. 

## Decomposition:

1. Dataset Collection & Annotation
* Gather large-scale images of Vietnamese food from various sources (public datasets, social media, food delivery platforms, etc.).​
* Annotate images with dish names (labels) and metadata (region, restaurant, etc.) to ensure accuracy and diversity.​

2. Data Preprocessing
* Clean and filter images to remove duplicates and poor-quality data.​
* Resize images to standardized dimensions suitable for deep learning models 
* Split the dataset into training, validation, and test sets.

3. Feature Extraction & Model Selection
* Choose a baseline model (e.g., ResNet, EfficientNet, Vision Transformer) suited for food classification tasks.​
* Extract features from images using CNN or Transformer-based architectures.​

4. Model Training
* Train the chosen model on the preprocessed dataset, applying common data augmentation techniques (e.g., SnapMix, rotation, flipping).​
* Fine-tune parameters to maximize performance and minimize overfitting.

5. Model Evaluation
* Test the model’s accuracy, top-k accuracy, F1-score, and confusion matrices.​
* Benchmark results against existing Vietnamese food classification datasets.​

6. Deployment & Inference
* Prepare the model for real-world inference (e.g., web app, mobile app, API).​
* Enable fast recognition of Vietnamese dishes from user-uploaded or real-time camera images.​

7. Postprocessing & Output Presentation
* Map predicted classes to standardized dish names and present additional information (nutrition, region, restaurant).
* Display detection results in user-friendly format, including confidence scores and optional bounding boxes for multi-food images.

### Data Gathering 
These pictures were collected from different sources to ensure its variety and complexity.

Google, Facebook, Shopee Food: Most of the images were gathered from these platforms by searching the dish name with some keyword like "food review" or "cooking".
Youtube: Frames from the video or shorts were extracted with the help from the Roboflow annotation tools.
Personal Collection: Some images were personally taken by using a smartphone to simulate the real-world situation of food detection.

### Data Annotation 
The bounding box annotation and labeling process was done by using Roboflow tools. To speed up the process, a YOLOv10m model was trained on a subset of the dataset and used for the Auto Label feature to help automatically annotate the remaining images before double-checking it manually.

### Data Processing
Some augmentation techniques were used to make sure the model can generalize well and to resolve the imbalance volume between classes.
* Bounding box cropping: Minimum zoom of 5% and a maximum of 20%.
* Bounding box flip: Flip vertically.
* Brightness adjustments: Between -15% and +15%.
* Mosaic augmentation
Overall, the total images obtained for training the model after the augmentation process are 171,699 images.

### Model selection 

#### Key reasons why YOLO is well suited for detection:

* Unified Detection Architecture: YOLO directly predicts bounding boxes and class probabilities from whole images in a single forward pass, enabling real-time processing with low latency.
* Speed: YOLO networks are optimized for fast inference, making them suitable for applications requiring real-time detection.
* Detection Focus: YOLO is an end-to-end object detection framework designed to detect multiple objects and their locations in images, whereas ResNet is a backbone convolutional network originally designed for image classification.
* Bounding Box Prediction: YOLO predicts bounding box coordinates and confidence scores simultaneously, whereas ResNet itself outputs feature maps and classification logits, needing external region proposal and bounding box regression modules for detection.
* Efficiency in Handling Multiple Objects: YOLO divides the image into grids and predicts multiple bounding boxes in parallel, efficiently detecting many objects simultaneously.

## Comparison with ResNet-based models
| Aspect                    | YOLO (You Only Look Once)                                        | ResNet (Residual Network)                         |
|---------------------------|------------------------------------------------------------------|--------------------------------------------------|
| **Purpose**               | End-to-end object detection                                     | Backbone feature extractor for detection or classification |
| **Design**                | Single-shot, detection in one pass                              | Originally for classification; uses as feature backbone in detectors |
| **Primary Use**           | Real-time, fast object detection                                | Feature extraction for detection/classification |
| **Speed**                 | Very fast; suitable for real-time applications (~milliseconds per image) | Slower; depends on detection architecture, often used with R-CNN family |
| **Inference Time**         | Low latency, high throughput                                    | Higher latency, computationally intensive     |
| **Accuracy**               | Very competitive; sometimes less precise on small objects but generally high | High quality features; when combined with detection heads, achieves high accuracy but slower |
| **Complexity**             | Single architecture; unified detection and classification      | Component in detection pipelines; needs external modules (e.g., RPN, RoI pooling) |
| **Detection Method**       | Predicts bounding boxes and class probabilities in one stage   | Used as feature extractor in two-stage detectors (Faster R-CNN, Mask R-CNN) |
| **Speed vs. Accuracy Trade-off** | Faster but slightly less accurate on small or cluttered objects | Typically more accurate but computationally heavy and slower |
| **Model Size**             | Relatively lightweight (depending on version)                     | Larger; backbone weights are big, detection head adds complexity |
| **Usage Complexity**       | Easier to deploy for real-time detection                         | More complex; involves hybrid detection architecture |
| **Typical frameworks**     | YOLOv5, YOLOv7, YOLOv8, etc.                                    | ResNet-50, ResNet-101 used in Faster R-CNN, Mask R-CNN, RetinaNet |
