---

## I. Objective
Design and implement a **data storage system** for saving user–chatbot conversations in the food recommendation application.  

Main requirements:
- Store chat history between users and the chatbot (Gemini API).  
- Ensure **anonymity** and **data security**.  
- Allow users to review their previous chat sessions.  
- Easily integrate with other modules (frontend, Gemini API, Map API).

---

## II. Sub-problem Analysis

| Component | Description | Expected Output |
|------------|--------------|------------------|
| **1. Conversation Storage** | Receive data from the backend when users send/receive messages, and store all chat content in the database. | JSON-based data structure containing messages. |
| **2. User Anonymization** | Generate an anonymous identifier (`anon_user_id` or `token`) instead of a real user account. | Unique token that contains no PII (Personally Identifiable Information). |
| **3. Data Security** | Encrypt chat content before saving. Do not store IPs or emails. | Encrypted data in the database. |
| **4. Conversation Retrieval** | Retrieve chat history based on the anonymous identifier. | `/get_history` API returning JSON data. |
| **5. Data Deletion & Management** | Add functionality to delete all chat history based on the anonymous token. | `/delete_history` API functions correctly. |

---

## III. Proposed Technologies

| Component | Tool/Library | Notes |
|------------|---------------|--------|
| **Backend** | Node.js + Express | Handles APIs for saving and retrieving chat data. |
| **Database** | MongoDB Atlas (cloud) | Stores JSON-based chat data; flexible and easy to deploy. |
| **Security** | AES-256 or Node.js `crypto` library | Encrypts chat content before saving. |
| **Anonymization** | UUID + locally stored token (localStorage) | Users do not need to log in. |
| **API Integration** | Call Gemini API to get responses and store them in the DB along with user messages. | Direct connection to the Gemini module. |
| **Map API** | Do not store map images; only save coordinates or address text. | Reduces storage and prevents location exposure. |

## V. Technology Comparison

| Criteria | PostgreSQL | MongoDB | Firebase |
|-----------|-------------|----------|-----------|
| **Data Model** | Rigid (tables/relations) | Flexible (JSON documents) | Flexible + Realtime |
| **Ease of Deployment** | Moderate | Easy | Very easy |
| **Chat Data Handling** | Good but requires joins | Good | Good |
| **Scalability** | High | High | Medium |
| **Project Fit** | Not necessary | Very suitable | Good if frontend-heavy |

> **Conclusion:**  
> **MongoDB Atlas** is chosen for storing chat history due to its flexible structure, easy API integration, and direct JSON storage capabilities.
