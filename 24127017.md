# Feedback & Rating System  
**Branch:** test_users_feedback_analytics  
**Person in charge:** Nguyen Ngoc Gia Bao  
**Project:** Food & Restaurant Recommendation (Flask + SQLite + Chart.js)

---

## I. Objective
Build a system for collecting and analyzing user feedback to evaluate the effectiveness of the interface, functionality, and user experience.

### Main Requirements:
- Collect **rating (0–5)** and **feedback text** from an HTML form.  
- Store data in **SQLite**.  
- Perform statistical analysis: average score, number of feedbacks, and charts.  
- Display dynamic charts using **Chart.js** on `chart.html`.  
- Keep **anonymity**, avoid storing personal information.

---

## II. Subtask Analysis

| Component | Description | Expected Output |
|------------|--------------|-----------------|
| 1️ Feedback Form | User inputs feedback and rating (0–5). | POST request containing {rating, feedback} |
| 2️ Data Storage | Write data into SQLite (table `feedbacks`). | New row in DB |
| 3️ Anonymization | Generate feedback_id automatically (UUID/autoincrement). | No name/email stored |
| 4️ Data Analysis | Calculate average score, count feedback by rating level. | JSON data for Chart.js |
| 5️ Display Results | Show statistical charts with **Chart.js**. | `chart.html` renders chart |
| 6️ Delete Data *(optional)* | Admin can delete all feedback. | `/delete_all` endpoint works |

## III. Technologies Used

| Component | Tool | Note |
|------------|------|------|
| **Backend** | Flask (Python) | Lightweight, easy to deploy |
| **Database** | SQLite | Local .db file, built-in integration |
| **Frontend** | HTML + Bootstrap + Chart.js | Interface + dynamic chart |
| **Anonymization** | Python uuid | Generate unique ID |
| **Data Analysis** | Flask route `/analytics` | Provide data for Chart.js |

---

## IV. Database Structure (SQLite)
```sql
CREATE TABLE feedbacks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  rating INTEGER NOT NULL,
  comment TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## V. Detailed Comparison Table

| **Criteria** | **Flask (chosen)** | **Django** | **FastAPI** |
|---------------|--------------------|-------------|--------------|
| **Complexity Level** | Lightweight, flexible, easy to customize for small projects | Heavy, includes many built-in modules | Easy and fast coding but requires Python 3.7+ |
| **Performance** | Stable for small–medium projects | Heavier due to ORM and large structure | Higher than Flask thanks to async |
| **Scalability** | Easily expandable via blueprints, plugins | High, suitable for large systems | Good but requires async knowledge |
| **Learning & Initial Setup** | Easy to learn, simple configuration | Harder, requires understanding MVC | Moderate, requires understanding typing and async |
| **Documentation & Community** | Broad, easy to find tutorials | Very strong and plugin-rich | Rapidly growing, smaller than Flask |
| **Suitability for Group Projects** | Suitable because it’s lightweight and modular (Feedback, Test) | Too heavy, unnecessary | Not stable enough for beginners in teamwork |
